# 블로그 → 인스타그램·스레드·카드뉴스

사용자가 “스레드용으로”, “인스타에 공유”, “블로그를 카드뉴스로”처럼 요청해도 매체에 맞는 문안과 이미지를 구성합니다. 설치만으로 계정 접근이나 공개 게시 권한이 생기지는 않습니다. 다른 로컬 스킬 없이 이 폴더만으로 사용할 수 있습니다.

## 요청 해석

- “글 써줘 / 스레드용으로 바꿔줘”는 문안 작성, “카드뉴스 만들어줘”는 이미지 파일 제작까지입니다. 문구나 기획안만으로 이미지 완성을 보고하지 않습니다.
- “올려줘 / 게시해줘”는 지정 채널의 실제 게시 요청입니다. 현재 대화에서 이미 허용한 범위는 재확인하지 않습니다. 계정·시간·대상이 모호하면 필요한 항목만 확인하고 제작 가능한 부분을 먼저 진행합니다.
- 채널 하나만 요청하면 그 채널만 처리합니다. Instagram→Threads 자동 공유, 뉴스레터·카카오톡·댓글·다른 SNS·반복 예약으로 범위를 늘리지 않습니다.

## 원문과 말투

1. 링크의 실제 본문을 읽고 제목, 날짜, 대상, 활동, 조건·예외, 숫자, 공개 URL, 사용할 이미지와 출처를 정리합니다. 제목·검색 요약만 보고 본문을 읽었다고 하지 않습니다. 접근이 막히면 제공된 본문으로 작업하고 미확인 부분을 표시합니다.
2. 현재 사용자의 지시와 승인 문안을 우선합니다. “그대로”이면 지정 부분만 수정합니다. [문체·캡션 형식](references/captions.md)을 읽습니다.
3. 모두잇 비비 명의이면 첫 문장을 정확히 `안녕하세요. 모두잇 AI 직원 비비입니다.`로 시작합니다. 캐시나 사용자의 본인 명의에 비비 인사를 넣지 않습니다. 처음 사용하는 다른 사람에게도 비비 명의를 강제로 적용하지 않습니다. [프로필 설정](references/profile.md)을 참고합니다.
4. 친근하고 담백한 존댓말, 짧은 논리 문단을 기본으로 합니다. Threads라고 무조건 반말로 바꾸지 않습니다. 실제로 하지 않은 경험·현장 반응·성과, 과장된 수식어를 만들지 않습니다.

## 채널별 구성

- **Threads:** 인사(해당 시) → 관심을 끄는 핵심 한 문장 → 변화·활용점 2~3개 → 원문 링크 → 요청된 하단 안내입니다. 질문은 자연스러울 때만 넣습니다. 기본은 한 게시물이며 길면 먼저 줄이고, 필요한 경우에만 연속 글로 나눕니다. 분할 게시도 실제 요청 범위를 따릅니다.
- **Instagram:** 인사(해당 시) → 첫 화면에서 이해되는 훅 → 내용·실습·효용 요약 → 원문/신청/문의 행동 안내 → 관련 해시태그입니다. 캡션 링크가 눌린다고 가정하지 않으며 실제 프로필 링크를 확인한 경우에만 “프로필 링크”라고 씁니다.
- 글자 제한·해시태그 수·첨부 장수·주제 선택은 과거 값을 영구 규칙으로 박아두지 않습니다. 게시 시 현재 작성창이나 공식 안내를 확인합니다. 공백·개행·URL·하단 안내까지 포함한 최종 문안 길이를 확인하고, 확인하지 못한 경우 “플랫폼 제한 검증 완료”라고 하지 않습니다. 초안 단계에서는 로컬 문자 수를 편집 참고값으로만 표시합니다.
- 강의 후기 공유에서 별도 카드뉴스 요청이 없으면 원문 대표 썸네일과 **그 강의의 실제 수업 사진** 2장을 기본으로 합니다. 사진이 없으면 다른 강의·생성 사진으로 대체하지 말고 문안까지 준비한 뒤 누락을 알립니다.

## 카드뉴스 제작

[카드 구성·디자인·실행 방법](references/cardnews.md)을 읽고 주제에 맞는 스타일을 고릅니다. 기본 출력은 **4:5, 1080×1350 PNG**이며 장수는 목적에 맞춥니다. 사용자가 정한 장수·규격·참고 디자인이 우선합니다.

1. 표지 → 핵심 내용 → 행동 안내 흐름으로 한 장에 메시지 하나를 배치합니다. 날짜·가격·인명·조건을 원문과 대조합니다.
2. 실제 제공 사진·허용된 공식 자료·생성 배경을 용도에 맞게 준비합니다. 실제 화면·현장 사진이 필요한 곳에 생성 장면을 넣지 않습니다. 설명용 AI 장면이면 실제 사진과 구분해 고지합니다.
3. 제공된 `examples/spec.json` 형식으로 원고를 쓰고 `scripts/render.mjs`로 PNG와 검수 보고서를 만듭니다. 한국어 문구는 이미지 생성 모델에 맡기지 않고 렌더러로 올립니다. 렌더러는 배경 이미지를 생성하지 않습니다.
4. 모든 장을 원본 크기와 약 250px 축소 크기로 직접 열어 한글·가독성·겹침·잘림·이미지 적합성을 검사합니다. 자동 검사는 내용 적합성이나 미적 완성도를 대신하지 않습니다. 실패한 장만 수정하고 성공한 이미지는 보존합니다.
5. QR을 사용할 때는 실제 목적지 URL과 디코딩 결과를 확인합니다. 생성 도구를 쓸 수 없으면 같은 URL의 텍스트 안내로 처리하고 QR을 만들었다고 하지 않습니다. 유료 생성 서비스의 비용·승인은 해당 환경의 정책과 현재 사용자 허용 범위를 따릅니다.

## 게시와 완료 보고

실제 게시 요청이 있을 때 [게시·검증 절차](references/publishing.md)를 읽습니다. 요청한 계정에서 전체 이미지 순서·원본 비율·최종 캡션·링크를 확인하고 게시합니다. 시간 초과 시 재시도 전에 공개 여부를 조회합니다.

결과에는 채널별 최종 문안, 카드 파일과 순서·규격·장수, 출처와 생성 이미지 고지, 검수 결과를 제공합니다. 제작·초안·예약·공개·미확인은 구분하며 실제 게시한 경우에만 채널별 공개 URL을 보고합니다.
